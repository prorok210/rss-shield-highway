# Эксперименты

Код экспериментов протокола (v11): основной генератор трафика, 86-признаковое наблюдение,
semi-MDP-переходы с накоплением наград при перехвате, DQN, счётчики раздела 7.7 и короткий
сквозной пилот цепочки обучения (раздел 8). Подтверждение H1–H3 на этом этапе не выполняется.

| Модуль | Содержание |
|---|---|
| `generator.py` | `ProtocolHighwayEnv`: 4 полосы, окно трафика плотности D (раздел 7.6): расстановка, прогрев 20 с без ego, рециркуляция окна, вставка ego (не более 2 удалений), признаки небезопасного старта по ρ; наблюдение из 86 признаков (75 кинематических + команда в FIFO + brake_mode + целевая скорость + целевая − текущая полоса); сохранение и восстановление стартового состояния |
| `env.py` | единственное место создания среды; при импорте включает `fast_road` (`RSS_FAST_ROAD=0` выключает); кэш стартовых состояний `start_states/D{D}_seed{seed}.pkl` |
| `rewards.py` | награды R_v и R_S (раздел 2) |
| `dqn.py` | DQN на NumPy: 2×256 ReLU, Adam, функция потерь Хьюбера, целевая сеть, цель с максимумом по A_safe(s′); буфер (s, a, R, s′, d, n, маска(s′)); сохранение и загрузка `.npz` |
| `runner.py` | эпизод с фильтром: шаги политики и перехвата, сборка semi-MDP-переходов, счётчики E, N_att, N_blocked, N_att_int, N_exec, N_exec_int, R_int, BLCR, v_eff, JerkRMS; журнал шагов со статусами `policy_step`, `intervention`, `active`, `brake_mode`, `sup_active`, `return_active`, `fallback` |
| `pilot.py` | пилот: прогрев, стартовые состояния, обучение, записи буфера до, во время и после перехвата, сохранение и загрузка модели, оценочный эпизод, итоговые счётчики, диагностика бокового порога; отчёт `report.md` |
| `tests/` | 10 тестов цепочки |

DQN написан на NumPy, поэтому зависимости обучения совпадают с `requirements.txt`; отдельный
`requirements-train.txt` не нужен. Градиенты проверяются конечными разностями в тестах.

## Запуск

Из корня репозитория:

```bash
python -m pytest -q experiments/tests
python -m experiments.pilot --out runs/pilot_local            # пилот раздела 8
python -m experiments.pilot --out runs/pilot_quick --quick    # укороченный вариант для отладки
```

В CI пилот запускает `.github/workflows/pilot.yml`; `report.md` публикуется комментарием к PR,
все файлы пилота — в артефакте запуска. Модели `.npz` в git не кладутся.

## Требования к коду экспериментов

1. Среда создаётся только в `env.py`, и при его импорте вызывается `from sim import fast_road; fast_road.enable()`. Так ускорение включено в каждом процессе, включая воркеры, которые macOS запускает через spawn.
2. Состояние на момент вставки ego (после прогрева) для валидации, dev и теста рассчитывается один раз на пару (D, сид). Оно сохраняется в `start_states/` вместе с состоянием генератора случайных чисел и переиспользуется всеми политиками, ρ и режимами (`env.reset_cached`). Тест `test_start_state_cache_is_bit_identical`: эпизод из сохранённого состояния побитово совпадает с эпизодом, посчитанным с нуля.
3. Счёт — очередь независимых задач (запуск обучения или блок эпизодов ячейки), по процессу на ядро. В каждом процессе один поток: `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `VECLIB_MAXIMUM_THREADS=1` (пилот задаёт их сам до импорта NumPy). При перезапуске готовые задачи пропускаются. На macOS очередь запускается через `caffeinate -i`.
4. Каждая задача выполняется целиком на одной машине. В её журнал пишутся машина, ОС, модель CPU, версии пакетов и хэш коммита (`journal.md` пилота).
5. До счёта на каждой машине выполняются `python -m pytest -q sim/test_fast_road.py` и `python sim/bench.py fast`; время шага идёт в раздел 8 протокола. Тест эквивалентности выполняется на основном генераторе (`generator.py`), упрощённый `sim/window_env.py` для него больше не используется.
